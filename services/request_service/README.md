## Запуск микросервиса request_service

### 1. Клонирование репозитория

```bash
git clone https://github.com/Nikita5283/electro-warranty.git
cd electro-warranty
```

### 2. Создание и активация виртуального окружения

**Linux / macOS:**
  ```bash
  python3 -m venv .venv
  source .venv/bin/activate
  ```
**Windows (PowerShell):**
  ```powershell
  python -m venv .venv
  .venv\Scripts\Activate.ps1
  ```
**Windows (cmd):**
  ```cmd
  python -m venv .venv
  .venv\Scripts\activate.bat
  ```

### 3. Установка зависимостей

```bash
pip install -r requirements.txt
```

### 4. Запуск микросервиса

```bash
cd services/request_service
uvicorn main:app --reload --port 8003
```

После старта будут доступны:
* **Интерактивная документация Swagger UI:** [http://127.0.0.1:8003/docs](http://127.0.0.1:8003/docs)
* **Альтернативная документация ReDoc:** [http://127.0.0.1:8003/redoc](http://127.0.0.1:8003/redoc)
* **Проверка состояния сервиса (Health Check):** [http://127.0.0.1:8003/health](http://127.0.0.1:8003/health)

## Сценарии демонстрации паттернов в Swagger UI

Для демонстрации работы паттернов откройте [http://127.0.0.1:8003/docs](http://127.0.0.1:8003/docs):

### 1 Демонстрация Chain of Responsibility (Цепочка обязанностей)
1. Выберите эндпоинт `POST /api/v1/requests` и нажмите **Try it out**.
2. В обязательном заголовке `X-User-Id` укажите значение `USER0001`.
3. В теле запроса укажите ID покупки с намеренно истекшей гарантией:
   ```json
   {
     "purchase_id": "EXPIRED1",
     "problem_description": "Не включается дисплей"
   }
   ```
4. Нажмите **Execute**.
5. **Результат:** Сервис возвращает HTTP-код `422 Unprocessable Entity` с текстом:
   ```json
   {
     "detail": "Срок действия гарантии по данному товару истёк"
   }
   ```
   *Первое звено (проверка владельца) пройдено успешно, второе звено цепочки перехватило просроченную дату гарантии.*

---

### 2 Демонстрация Facade, Factory Method, Adapter и Observer
1. В том же методе `POST /api/v1/requests` с заголовком `X-User-Id: USER0001` введите валидный ID покупки:
   ```json
   {
     "purchase_id": "PURCH001",
     "problem_description": "Не заряжается аккумулятор"
   }
   ```
2. Нажмите **Execute**.
3. **Результат:** Сервис возвращает HTTP-код `201 Created`:
   * `Facade` скоординировал работу компонентов.
   * `Factory Method` предоставил клиент данных.
   * `Adapter` нормализовал данные покупки.
   * `Observer` автоматически создал первую запись в массиве `history`:
   ```json
   {
     "id": "A1B2C3D4",
     "purchase_id": "PURCH001",
     "client_id": "USER0001",
     "status": "принят",
     "history": [
       {
         "status": "принят",
         "comment": "Заявка создана клиентом"
       }
     ]
   }
   ```
   *(Скопируйте сгенерированный 8-символьный `id` заявки для следующих шагов).*

---

### 3 Взятие заявки в работу сотрудником (assign) и паттерн State
1. Попробуйте изменить статус заявки до её назначения сотруднику через `POST /api/v1/requests/{request_id}/status`:
   сервис вернёт ошибку `400 Bad Request` ("Нельзя изменить статус заявки: она ещё не взята в работу сотрудником").
2. Откройте метод `POST /api/v1/requests/{request_id}/assign`.
3. В поле `request_id` укажите ID заявки, в обязательном заголовке `X-User-Id` укажите `EMP00001` и нажмите **Execute**.
   Заявка переходит в работу сотрудника.
4. Откройте метод `POST /api/v1/requests/{request_id}/status` с заголовком `X-User-Id: EMP00001`.
5. Попробуйте сразу перевести заявку в финальный статус в обход регламента:
   ```json
   {
     "status": "товар выдан покупателю"
   }
   ```
6. Нажмите **Execute**.
7. **Результат:** Паттерн `State` отклоняет операцию с кодом `422`:
   ```json
   {
     "detail": "Переход из статуса 'принят' в 'товар выдан покупателю' запрещён. Следующий допустимый статус: 'товар принят в сервис'"
   }
   ```

---

### 4 Демонстрация паттерна Proxy и работы с ячейками постамата
1. Переведите заявку в статус `"товар принят в сервис"`, а затем в `"товар на обслуживании"` (последовательными вызовами метода смены статуса с заголовком `X-User-Id: EMP00001`).
2. На шаге перевода в `"товар обслужен"` попробуйте указать занятую ячейку:
   ```json
   {
     "status": "товар обслужен",
     "cell_code": "CELL-BUSY"
   }
   ```
3. Нажмите **Execute**.
4. **Результат:** `LoggingClientProxy` перехватывает конфликт постамата и возвращает код `409 Conflict`:
   ```json
   {
     "detail": "Ячейка CELL-BUSY уже занята, выберите другую свободную ячейку"
   }
   ```
5. Укажите свободную ячейку `"A-101"`. Запрос выполнится успешно (`200 OK`). Ячейка занимается с защитой транзакции (компенсация освобождения при ошибке БД).
6. Переведите заявку в статус `"товар выдан покупателю"`. Ячейка автоматически освобождается после сохранения в БД, заявка заполняет поле `closed_at` в UTC, а подписчик `Observer` асинхронно уведомляет `stats-service` о факте закрытия заявки.
