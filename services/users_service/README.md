# Users Service

Микросервис отвечает за регистрацию пользователей, аутентификацию с выдачей JWT-токенов (HS256), валидацию токенов для API Gateway и хранение учетных записей с ролевым доступом.

---

## Запуск

```bash
cd services/users_service
uvicorn main:app --reload --port 8001
```

**Swagger UI:** [http://127.0.0.1:8001/docs](http://127.0.0.1:8001/docs)  
**ReDoc:** [http://127.0.0.1:8001/redoc](http://127.0.0.1:8001/redoc)  
**Проверка состояния:** [http://127.0.0.1:8001/health](http://127.0.0.1:8001/health)

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `USERS_DB_URL` | `sqlite:///./users.db` | Строка подключения к БД SQLite / PostgreSQL |
| `JWT_SECRET` | `electro-warranty-jwt-super-secret-key-2025` | Секретный ключ для подписи JWT-токенов (HMAC-SHA256) |
| `TOKEN_EXPIRE_HOURS` | `24` | Время жизни access токена в часах |
| `SEED_USERS` | `true` | Инициализировать ли тестовых пользователей при первом запуске |

## Методы

| Метод и путь | Кто вызывает | Описание | Коды ответов |
|---|---|---|---|
| `GET /health` | Мониторинг, Gateway | Проверка доступности сервиса и соединения с БД | `200`, `503` |
| `POST /api/v1/auth/register` | Клиент через Gateway | Регистрация нового аккаунта (по умолчанию роль `CLIENT`) | `201`, `409` (дубликат email), `422` |
| `POST /api/v1/auth/login` | Все пользователи | Вход по логину и паролю, получение JWT-токена | `200`, `401` |
| `GET /api/v1/users` | Менеджер / Админ | Список пользователей системы (с фильтром `?role=...`) | `200` |
| `GET /api/v1/users/{id}` | Сотрудник / Менеджер | Профиль пользователя (данные клиента для карточки заявки) | `200`, `404` |
| `POST /internal/auth/verify` | **API Gateway** | Валидация JWT-токена, возврат `user_id` и `role` | `200`, `401` |
| `GET /internal/users/{id}` | **stats-service** | Получение ФИО сотрудника для формирования отчётов | `200`, `404` |

## Паттерны

1. **Singleton** - `UsersConfigSingleton`
   Обеспечивает единую точку доступа к конфигурации микросервиса (настройки JWT, строки подключения, параметры сидинга).
2. **Strategy**:  
   `PasswordHasher` - безопасное хеширование паролей с уникальной солью на базе стандарта PBKDF2-HMAC-SHA256 (100 000 итераций).  
   `JwtTokenProvider` - генерация и криптографическая верификация цифровой подписи JWT токенов (RFC 7519, HS256).
3. **Chain of Responsibility** - `UserValidationHandler`:  
   `EmailUniquenessHandler` - проверка заполненности и уникальности email адреса (предотвращение дубликатов).  
   `PasswordComplexityHandler` - валидация минимальной длины и стойкости пароля.  
   `RoleValidationHandler` - проверка корректности назначаемой роли (`CLIENT`, `EMPLOYEE`, `MANAGER`, `ADMIN`).  
4. **Observer** - `UserObserver`:  
   `AuditLogObserver` - автоматическое протоколирование событий безопасности (регистрация, успешный вход, отказы) в logs/users-service.log.
5. **Facade** - `UsersServiceFacade`:  
   Изолирует контроллеры FastAPI от деталей БД, хеширования и валидации, предоставляя единый лаконичный интерфейс взаимодействия.
